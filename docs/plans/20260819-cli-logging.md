# Понятное логирование работы CLI

## Overview

Добавить постоянные краткие сообщения о ходе сборки EPUB: загрузке выпуска, количестве найденных материалов, последовательной загрузке статей, сборке EPUB с изображениями и публикации результата. Логи направлять в stderr; stdout по-прежнему содержит только путь готового файла.

## Context

- Files involved: `main.go`, `main_test.go`, `validation_test.go`, `README.md`
- Related patterns: последовательная оркестрация в `run`, `redactURL` для безопасного вывода URL, раздельные `stdout` и `stderr`
- Dependencies: новые зависимости не нужны; использовать стандартный `log.Logger`
- Не добавлять флаги уровней логирования, структурированные логи или отдельную абстракцию логгера
- Не добавлять тесты на наличие, текст, порядок или количество сообщений логирования

## Development Approach

- **Testing approach**: Regular — изменить реализацию, затем адаптировать существующие тесты
- Создать в `run` человекочитаемый logger для stderr без временных меток
- Логировать только границы длительных этапов, не каждый внутренний вызов
- URL выводить только через `redactURL`, а удалённые и пользовательские значения — в экранированном виде
- Сохранить текущие fail-fast семантику, атомарную публикацию и формат stdout
- Существующие сквозные тесты должны перестать требовать пустой stderr, но не должны проверять содержимое логов
- Полностью завершать каждую задачу и запускать тесты до перехода к следующей
